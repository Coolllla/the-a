# 「整图底材 + 百分比叠层」的隐式契约：容器高度只能由底材决定

> 起因：CardWorl 的 avatar / SEE MORE 两个叠层纵向对不上底图，且**换设备后偏移量不一样**，一度误判成设备/DPR/rem 的问题。真凶是文字块留在了普通流里。

## 病根

出问题时的结构（`CardWorl.tsx`）：

```tsx
<div className={styles.card}>          // position: relative，无显式 height
  <Image className={styles.base} />    // width:100% height:auto —— in-flow
  <motion.div className={styles.avatarLayer} />  // absolute，top: 33.5%
  <div>                                // ← 无 className，static，in-flow ❌
    <p><TypeWriter /></p>
    <p><TypeWriter /></p>
  </div>
  <Link className={styles.more} />     // absolute，top: 74.5%
</div>
```

五步推导：

1. `.card` 没有显式高度 → 高度由 **in-flow 子元素**垂直堆叠撑出来。
2. 设计意图是「底材定高」：`.base` 的 `width:100% / height:auto` 让它按原生比例（1373:1198）算出高度，于是 `.card` 高度 ≡ 底图高度。
3. 但文字 `<div>` 也是 in-flow static，它排在 `.base` **下面**，于是 `.card` 高度变成 `底图高 + 文字块高`。
4. CSS 规范里，绝对定位元素的 `top: <percentage>` 解析基准是 **containing block 的 height**（这里是 `.card` 的 padding box）。基准一变高，同一个 `33.5%` 就落到画面更下方。
5. 而 `left / width` 的百分比基准是 **width**，没被污染 —— 所以症状是「**横向严丝合缝、纵向整体下移**」。

## 为什么伪装成「换设备的问题」

文字块的高度不是常量，它至少受这四件事影响：

- **字体可用性** —— PS 里用的字没进 `fonts.ts` 时走 fallback，不同系统的 fallback 字体 metrics（ascent / descent / line-gap）不同 → line-height 不同；
- **`.card` 的实际宽度** —— `min(84rem, 72vw)` 会随视口在两个分支间切换，宽度变了文字换行行数就变；
- **`<p>` 的默认 margin** —— `1em`，随 font-size 浮动；
- **根 font-size** —— `globals.scss` 是 `html { font-size: 62.5% }`，这是**相对浏览器默认字号**的，用户改过默认字号或开了最小字号限制，1rem 就不是 10px。

每一项都可能跨设备不同 → 污染量不同 → 偏移量不同。所以表现为「这台对、那台不对」，但病根是结构性的，跟设备无关。

**反直觉的点**：当时两个 `TypeWriter` 的 `text` 还是空字符串 `""`，照样污染。空文案 ≠ 零高度 —— `<p>` 仍然占一个 line box + 上下 margin。

## 为什么改成绝对定位就好了

`position: absolute` 把文字块移出普通流（out-of-flow）→ 不再参与父级高度计算 → `.card` 高度重新只由 `.base` 决定 → 所有 `top: %` 的基准恢复成「底图高度」，跟 PS 里量的画布一致。

## 为什么不能「量一下偏了多少再补偿」

margin 折叠会让污染量算不出来：文字 div 没有 border / padding，第一个 `<p>` 的 `margin-top` 会穿透 div、再跟 `.base` 做相邻兄弟折叠（取 max）；最后一个 `<p>` 的 `margin-bottom` 同样穿透 div，又因为 `.card` 也没有 padding / border（`position: relative` **不**创建 BFC），直接**折叠出 `.card` 之外**，压根不计入 `.card` 高度。

也就是说污染量 ≈ `1em 折叠后的上边距 + 若干 line box`，而尾部 margin 凭空消失。这个数既不好算、也随字体和换行变。**补偿式调百分比是个陷阱，必须把元素移出流。**

## 结论 / 以后怎么写

「整图底材 + 百分比叠层」这个语法有一条不成文的前置条件：**容器的高度必须只由底材决定**。所以：

1. 除底材外，`.card` 的**所有**子元素都必须 out-of-flow。混进任何一个 in-flow 元素（文字、按钮、`<br>`、甚至一个只有 margin 的空 div）都会污染纵向基准。
2. 口诀：**横向百分比基准是 width（一般安全），纵向百分比基准是 height（容易被流内元素污染）**。这类 bug 的典型指纹就是「横向对、纵向整体下移」，看到这个症状先查流。
3. **更稳的防御 —— 把隐式契约变成显式声明**：给 `.card` 钉死比例，底材也退出流。

   ```scss
   .card {
     position: relative;
     width: min(84rem, 72vw);
     aspect-ratio: 1373 / 1198;   // 显式声明高度，不再依赖「谁在流里」
   }
   .base {
     position: absolute;
     inset: 0;
     width: 100%;
     height: 100%;
   }
   ```

   这样即便以后有人不小心塞了个 in-flow 元素，容器高度也不会变，叠层不会移位。代价是换底材时要同步改 `aspect-ratio` 的两个数字。
