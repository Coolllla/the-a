# 2026-07-29 动画编排：不做编辑器，做调参台（约定部分是待定草稿）

> **状态**：§一 的结论已定（有依据、可执行）。**§二 的写法约定是草稿，未采纳** —— 项目里还没有一幕真实的 timeline 演出，纸上定约定必然是猜。等写完一到两幕后拿 §三 的清单回来验，再决定哪几条留、哪几条删、要不要毕业成 `doc/decisions/motion.md`。

> 起因：预期后续会有比较多需要编排 timeline 的动画，问要不要开发一个"快捷方便的动画编排工具"。

## 一、已定的结论

### 1. 不做自研可视化编排器，做 dev 调参台

"编排工具"和"调参台"经常被混为一谈，成本差一个数量级：

- **编排工具（authoring）**：界面里拖关键帧、生成代码 → 时间轴 UI + 拖拽 + 序列化 + 代码生成，最少一两周
- **调参台（debugging）**：已写好的 timeline 能重播、拖时间、变速、看降级 → 现成插件 + 一层包装，半天

真正的痛点是后者。[7-27 log](../logs/2026-07-27-library-skeleton.md) §G 已经写下过：

> 开屏动画最耗人的不是写，是"每改一个 delay 就刷新一次看两秒"

这句描述的是调参，不是编排。

不做编排器的理由：

| 理由 | 依据 |
|---|---|
| 编排工具的收益随**同构演出的数量**增长，本项目正好反着 | [architecture.md §六](../decisions/architecture.md)：「版本之间应该差异巨大，**共享框架是反模式**」。每一幕都是一次性的美术命题，抽不出可复用的编排语法 |
| 演出内容强依赖美术资产，资产未就位时**没有编排对象** | 7-27 那次实现被回退的根因（该 log §复盘） |
| GUI 产出的代码难读难 diff | 与「SCSS 手写复杂关键帧、视觉控制权 100% 在自己手上」的项目哲学冲突 |
| 工具会长成第二个项目 | 抢站点本体工期，且简历价值低于站点本身 |

现成的可视化编辑器只有 **Theatre.js** 一个真选项（浏览器内拖关键帧、可驱动任意 JS 值）。两个问题：长期没有大版本更新，接入前要先确认维护状态；它取代的是 GSAP timeline 本身，等于推翻 [tech-stack.md §3.5](../decisions/tech-stack.md) 的选型。不值得。

### 2. 家当盘点：一半已经装好了

`gsap@3.15` 自带全部原 Club 插件（Webflow 收购后免费，见 §3.5）。`node_modules/gsap/` 里现成可用：

| 插件 | 用途 |
|---|---|
| `GSDevTools` | 时间轴 scrubber：播放/暂停/拖时间/变速/选 timeline。**正是上面那句痛点的解药** |
| `MotionPathHelper` | 浏览器里直接拖贝塞尔运动路径 |
| `CustomEase` | 自定义缓动曲线（配官方在线曲线编辑器） |
| `Flip` | 状态间自动补间（两视图 morph 切换将来可能用） |

不需要新装任何包。

### 3. 术语：幕（Act）/ 剧场（Scene）

沿用 §3.5 已有的说法拆成两类，**它们的调试工具不一样**，不要塞进一个抽象：

| | **幕（Act）** | **剧场（Scene）** |
|---|---|---|
| 驱动 | 时间 | 滚动位置（ScrollTrigger） |
| 例子 | 开屏、转场、点击触发的小演出 | 藏书阁时间轴立绘推进、章节封面 |
| 生命周期 | 触发一次，播完交棒 | 常驻，随滚动来回 |
| 调试工具 | **GSDevTools**（拖时间轴） | **`markers: true` + 滚动位置滑块**（GSDevTools 用不上——时间由滚动决定） |

> ⚠️ 「幕」是本文新造的词，不要和 [architecture.md](../decisions/architecture.md) 剧院三层模型里的「演出 = 体验层的一个页面版本」混淆。一个"演出"（如 `library/v1`）里可以有若干"幕"和"剧场"。

**边界**：这套只管 GSAP。Motion（原 Framer Motion）负责的 UI 级动画（弹窗、悬停、列表进退场）不进这套约定——分工见 §3.5，不要让它蔓延。

#### L0 落地记录（2026-07-29）

`app/_lib/motion/devtools.ts`，导出一个 `attachDevTools(animation, id)`。`tsc --noEmit` 与 `eslint` 均通过。

```ts
useGSAP(() => {
  const tl = buildTimeline();
  return attachDevTools(tl, "library-intro");   // useGSAP 清理时自动调用返回的卸载函数
}, { scope });
```

三个实现决定，都记在文件头注释里：

- **摇树靠 `process.env.NODE_ENV` 的早返回语句**。`import("gsap/GSDevTools")` 落在不可达分支里，生产不进 bundle。⚠️ 改成三元或先存变量再判断可能破坏摇树，动之前先验 bundle。
- **`globalSync: false`**。默认 `true` 会连带拖动全局时间轴，把页面上其他动画（如首页 `useParallax` 的鼠标跟随）一起拽走，看起来像坏了。
- **`persist: true`** + `getById(id)?.kill()`。前者跨刷新记住 timeScale 与 in/out 点（正是"改个 delay 就刷新"那个痛点），后者防 HMR 重挂叠出多条控制条。

⚠️ **未经真实运行验证**：项目里还没有 timeline，这个模块目前**零调用点**。第一幕接上时要重点看两件事——插件是 `await import` 异步到位的，若幕在插件加载完成前就开播，控制条可能接在半途（草稿约定里"timeline 建出来时 `paused: true`，由机制决定何时 play"正好能规避，但没验过）。

## 二、约定草稿（**未采纳**，写完一到两幕后再回来看）

### 为什么现在不定

约定的价值全在"避免了什么真实代价"。没写过真实的幕，"真实代价"只能靠想 —— 想出来的约定有两种失败模式，本次讨论里两种都出现过：

1. **为整齐而整齐**：见 §四 被推翻的那条。
2. **为一个不存在的用例造抽象**：`defineAct` 这层包装现在只服务一个还没写的幕，符合 architecture.md §六 警告的过度设计形状。

所以下面按"违反了会怎样"分三层记下来，**附上每条的理由**，方便回头判断是真需要还是想多了。

### ① 结构约定（候选：硬 —— 有跨文件 / 跨版本后果）

| 候选约定 | 理由 |
|---|---|
| 三文件分工：幕本体是纯函数不认识 React / 生命周期在 React 组件 / CSS 管视觉 | v2 换演出只换一个文件。承 7-27 log §G「`introTimeline.ts` 写成 `(targets, onComplete) => gsap.timeline`」 |
| `data-act="…"` 属性取元素，不传 ref | 加一个入场元素只需在 JSX 加个属性，不用改幕函数签名。承 7-27 log §F |
| 机制放 `_lib/motion/`，幕本体留 `_experiences/<page>/v<N>/` | 三层模型：机制稳定、演出版本化 |
| 调参台不做自动注册表，自己维护显式 import 列表 | 全局注册表被生产代码 import 会把每一幕都拽进 bundle |

参考目录形态（草稿）：

```
app/_lib/motion/                    机制层（写一次，全站共用）
app/_experiences/library/v1/timeline/intro/
  Intro.tsx                         生命周期：播不播 / 锁滚动 / 播完交棒
  introAct.ts                       幕本体：纯函数 ← 调参只碰这个
  Intro.module.scss                 视觉 + 需要 SSR 就位的初始态
```

### ② 陷阱清单（候选：硬 —— 违反了就是 bug，且都难查）

| 陷阱 | 后果 | 来源 |
|---|---|---|
| **初始值单一来源**：一个元素的一个属性，初始值要么在 CSS 的 pending 态里、要么在 `from()` 里，**不能都写** | 改一处忘另一处，进场起点悄悄不对 | 7-27 log 记的代价条 |
| GSAP 必须**自己**处理 `prefers-reduced-motion` | `globals.scss` 那条全局规则只压 `animation-duration` / `animation-iteration-count` / `transition-duration`，**压不住 GSAP 写的 inline style** | 7-27 log §坑A。该 log 标注「这是现有降级机制的一个真空，出现第二处 GSAP 演出时应毕业到 `decisions/`」 |
| 首帧可见且要进场的元素，初始态必须在 SSR 就位（FOUC） | 终态闪现一帧 | [7-24 转场调研](7.24-转场动画调研.md) 末节。**但注意适用范围比原文窄**：幕布盖住的元素、首屏之外的元素都不受这条约束 —— 开屏那一整幕其实基本不受 |
| 同一元素同一属性叠多个 `from()` 时，第二个起要 `immediateRender: false` | `from()` 默认创建即渲染起始值，后建的会盖掉先建的，timeline 还没播状态就错了 | GSAP 通用坑，尚未在本项目撞到 |
| 播完别留残余 inline transform（终态==常态，或收尾清掉） | 和将来的 Motion layout 动画抢同一批属性 | 7-27 log 关于 pin 与 Motion 冲突那条的同源问题 |
| 剧场用 `position: sticky` 钉舞台，不用 ScrollTrigger 的 `pin` | `pin` 插 pin-spacer 改 DOM 结构，和 Motion layout 动画打架，且不好预测 | 7-27 log 已定 |
| 开屏锁滚动解除后必须 `ScrollTrigger.refresh()` | 滚动触发点位算错 | 7-27 log 已定 |

### ③ 写法建议（软 —— 说清利弊，写的时候自己挑，不设禁令）

- **`from` / `to` / `fromTo` 按哪个表达得清楚来选。** 「从 1.4 倍缩到正常」`from({ scale: 1.4 })` 就是自然写法，进场量本身是设计语言；常态值依赖布局测量（`x` 落到计算位置、`width: auto`）时 `from()` 更是唯一自然解，因为 GSAP 会自己读 DOM 当前值。只要不违反 ② 的「初始值单一来源」，用哪个都行。
- **时间点：绝对秒 vs 相对位置**（`"+=0.2"` / `"<"`）。绝对秒的好处是代码逐行就是节奏表、改一个数不牵连下游；相对位置的好处是中间插一段后面自动顺移。调固定编排时前者顺手，还在改结构时后者省事。
- ease 收成文件顶部常量，不散落在各 tween 里。
- 文件头留一张 `| 时间 | 发生什么 | ease |` 的注释节奏表（7-27 log §开屏节奏 已有雏形），代码顺序与表一致。
- 具体动效数值（时长、延迟、位移、曲线）**归用户填**，AI 只搭结构。

### 机制层要吞掉什么（`defineAct` / `useAct` 草稿职责）

写第一幕时验证这几件是不是真值得抽出来：

1. `prefers-reduced-motion` 判断 + 降级（让 ② 那条真空**只补一次**）
2. `data-act-state` 状态机：`pending → playing → done`
3. dev 重播（换 key 重挂 + `force` 忽略 sessionStorage）+ 把 timeline 交给 GSDevTools
4. `lockScroll`（**已定：作为 option 收进来**）—— 锁滚动 + `history.scrollRestoration = "manual"` + 解锁后 `ScrollTrigger.refresh()` 这套动作值得只写一次
5. 幕元素查询 `t(name)`：按 `data-act` 取、返回数组（一个名字可对应多个元素做 `stagger`）、取不到返回 `[]` 让 tween 空转而不是崩、dev 下 warn

其中第 5 条的"取不到不崩"是为了美术资产未就位时缺个元素不炸整幕 —— **但它也可能掩盖真 bug，回头要验**。

## 四、讨论留痕：被推翻的一条

初稿曾定「**幕里只用 `to()`，禁止 `from()` / `fromTo()`**」，理由是初始值只留 CSS 一个来源、顺带让 reduced-motion 用 `progress(1)` 白拿终态。

**被推翻的过程**（用户指出）：`to()` 要求写出常态值。「从 1.4 倍缩到正常」被逼成 `to({ scale: 1 })` 后，进场量 1.4 得挪进 SCSS —— 一个设计决策劈成两个文件，调"进场再大一点"要跨文件；常态值依赖布局测量时更是根本写不出来。

第一次修订：改成"按属性选 CSS 起手 / JS 起手"的混合规则 —— 仍然是错的方向，只是把一条硬规则换成两条。

**最终认识**：`from` / `to` 是每条 tween 的局部选择，没有跨文件后果、不影响 bundle、任何看 GSAP 的人一眼就懂，**不需要统一**。真正会出 bug 的只是"同一属性的初始值写了两遍"，那是一条不变量，已收进 ② 第一行。我把不变量写成了写法规定，是**为整齐而整齐**。

**留痕的原因**：这是本次讨论里"纸上定约定"的失败样本，也是 §二 整体推迟采纳的直接理由。
