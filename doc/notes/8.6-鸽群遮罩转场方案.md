## 关键认知：遮罩转场比共享元素动画**简单**

直觉上"一群鸽子飞过去"听着比淡入淡出难得多，但对代码结构的要求反而更松：

**切换发生在幕布之下，所以新旧视图不需要共存。** 于是：

- 不需要 `AnimatePresence`、不需要 `layoutId`、不需要 GSAP `Flip`
- `{view ? <Extra /> : <Timeline />}` 这个三元**完全够用**，只要在"鸽群完全遮屏"那一帧翻转它

对比一下：如果要做的是「时间轴节点飞散重排成番外卡片」那种共享元素形变，才必须让新旧元素同时挂在树上（那是 `layoutId` / `Flip` 的场景），也才必须留出重叠窗口。

## 为什么不用 View Transitions

[7.24 转场动画调研](./7.24-转场动画调研.md) 已经定了"先不用 View Transition"，这个结论在这里依然成立，而且有了新的理由：

View Transitions 的操作对象是**旧页面的截图**，擅长的是元素 morph 和 crossfade，**做不了自定义遮罩物**——没法让一群鸽子从截图里飞出来。这个转场必须自己控制，不走路由 API。

## 核心是一个四阶段状态机

state 不止 `view`，还要有 `phase`：

```
idle → covering（鸽群飞入） → [遮满：翻转 view] → revealing（鸽群飞出） → idle
```

```tsx
const [view, setView] = useState(false);
const [phase, setPhase] = useState<"idle" | "covering" | "revealing">("idle");

function switchTo(next) {
  if (phase !== "idle") return;   // ← 忽略连点，否则动画被打断
  setPhase("covering");
  // 鸽群飞入的 timeline 结束回调里：setView(next); setPhase("revealing");
}
```

两个必做的细节：

- **转场期间锁交互**：整页 `pointer-events: none`，外加上面那个 `phase !== "idle"` 的早退
- **全遮期要留够时长**（通常 100~200ms 完全不透明的窗口）。第一次做这类转场最常见的失败是"遮满即切、切完即散"，结果切换那一帧被眼睛捕捉到，看起来像闪了一下

## 鸽子用什么做（唯一的真决策点，取决于美术能出什么）

| 方案 | 前端成本 | 要美术出什么 | 备注 |
|---|---|---|---|
| **序列帧 sprite sheet** | 低 | 一只鸽子 6~8 帧拍翅循环，拼成长图 | `background-position` 配 `steps()` 步进。**推荐**，最可控 |
| Lottie / Rive | 中（要装包） | AE 或 Rive 工程文件 | 最专业，能控进度；Rive 体积小 |
| alpha 通道视频 | 低 | 一段带透明通道的鸽群 | ⚠️ 兼容性真坑：VP9-alpha 的 webm Safari 不支持，HEVC-alpha 只有 Safari 支持，要出两份 |
| 单张剪影 + transform 假装拍翅 | 最低 | 一张剪影 | 鸽子少、速度快时能糊过去，慢下来就露馅 |

**落地顺序建议：先用纯色矩形／圆点代替鸽子，把状态机和时序手感调通，再换素材。** 时序手感跟素材是独立的，美术没到位也能推进这一半。

## GSAP 侧：插件都已经在了

一群鸽子的错峰时序编排是 GSAP timeline 的主场（Motion 的 stagger + variants 也能做，但排时间轴不如它顺手）。查过 `node_modules/gsap/`，以下都在（3.15 起全插件免费，不用额外装）：

- **`MotionPathPlugin`** — 鸽子沿贝塞尔曲线飞，不是直线穿过
- **`MotionPathHelper`** — 能在浏览器里拖着调路径，调手感神器
- **`CustomEase`** — 起飞／掠过的加速度曲线
- **`Physics2DPlugin`** — 如果要"炸开／散开"的效果
- `Draggable` — 顺带一提，番外页那个环的拖拽旋转正好用它

⚠️ 别在同一批元素上混用 Motion 的 layout 动画和 GSAP 直接写 transform，会互相打架。

## 两个会咬人的坑

### 1. Nav 的 `z-index: 100`

`app/_shell/Nav/Nav.module.scss:13`，`position: fixed`。鸽群要盖住 Nav 就得比它高，不想盖就压在下面 —— 先决定，这影响转场层挂在哪。

另外：`position: fixed` 的祖先链上如果出现 `transform` / `filter` / `backdrop-filter`，会创建新的层叠上下文，fixed 会相对那个祖先定位而不是视口。目前 `/library` 那条链是干净的，别在中间加。

### 2. 全局那段 `prefers-reduced-motion` 管不住 GSAP

`globals.scss` 末尾那段只压 CSS 的 `animation-duration` / `transition-duration`，而 GSAP 直接写 inline transform，**完全绕过它**（这和 07-27 log 坑 A 是同一件事；也和 Lenis 相反 —— Lenis 的 `respectReducedMotion` 默认 true，自己处理）。

所以鸽群必须在 JS 里自己读 `matchMedia("(prefers-reduced-motion: reduce)")` 并降级成快速淡出淡入 —— 全屏飞掠对前庭敏感的人不友好。降级先例见 `app/_experiences/home/v1/cards/CardShell.tsx:25`。
