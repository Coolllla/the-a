# `<Link>` 的下划线为什么从子元素里取消不掉

> 起因：藏书阁的 `MeChapter` 里给内层 `<div className={styles.container}>` 写了 `text-decoration: none`，下划线纹丝不动。
> 已解决（把 `text-decoration: none` 挪到 `<Link>` 自己身上），但这个坑跨页面通用，单独记一条。

## 两件事叠在一起

### 1. 本项目 `globals.scss` 里没有 `a` 的全局 reset

grep 过一遍：全局样式里对 `a` 一个声明都没有。所以每个 `<a>`（含 `next/link` 渲染出来的）默认吃浏览器 UA 样式 —— **蓝紫色 + 下划线**都在。

推论：每个用到链接的组件都得自己关，`text-decoration: none` 和 `color: inherit` 要一起写，光关下划线会留一个蓝字。现成的先例在 [`app/_shell/Nav/Nav.module.scss`](../../app/_shell/Nav/Nav.module.scss) 的 `.link`（`text-decoration: none` + `color: var(--nav-fg)`）。

> 要不要加全局 reset 是用户的取舍：加了省事，但也会顺手把「正文里的行内链接」的下划线一起干掉，正文场景下划线是有用的。现状是不加、各组件自理。

### 2. `text-decoration` 是**画穿**子元素的，子元素关不掉

这是规范行为，不是 bug。[CSS Text Decoration §2.2](https://www.w3.org/TR/css-text-decor-3/#line-decoration)：装饰线由**设置它的那个元素**绘制，然后跨过所有后代的盒子继续画下去。后代自己声明 `text-decoration: none` 只是说「我不产生新的装饰线」，管不了祖先已经画在它身上的那条。

```scss
// ❌ 没用 —— 线是 <a> 画的
.container { text-decoration: none; }

// ✅ 关在 <a> 自己身上
.link { text-decoration: none; color: inherit; }
```

## 一个会骗人的「自愈」

装饰线**不会**传播到这两类后代：

- 脱离普通流的（`position: absolute` / `float`）
- 原子行内盒（`display: inline-block` / `inline-flex` / `inline-grid` / `table` 等）

所以给内层 div 加上 `position: absolute` 或 `display: inline-block` 之后，下划线会「自己消失」。**这是副作用，不是修好了** —— 哪天把定位方式改回普通流，下划线就原地复活，而那时候已经想不起来是这个原因了。老老实实关在 `<a>` 上。

## 顺带：CSS Modules 里的裸字符串 className

同一个文件里 `<div className="content">` 是裸字符串，CSS Modules 不会把它和 `.content` 对上（构建后类名带 hash）。这类写法不报错、不警告，只是样式静默不生效 —— 排查「样式没上」时先确认是不是漏了 `styles.`。
